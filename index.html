Fintech · Cashi · 2025 to present

From dashboard timeouts to under 5 seconds

Cashi's reporting runs on about 600-700 million records. Looker Studio dashboards would load for 2 to 5 minutes and then time out, and Power BI reports were slow to open.

I moved the Looker Studio dashboards to Extract Data sources, which cache the data and refresh on a schedule. I also created materialized views in Amazon Redshift and restructured Power BI data models and reports.

Input

About 600-700M records behind Looker Studio and Power BI reports

Work

Extract Data sources, SQL optimization, Redshift materialized views and leaner Power BI models

Output

2-5 minutes and a timeout, now under 5 secondsDashboards now load as soon as they open

Insurance · Beyond Insurance Brokerage · 2023 to 2025

Automating updates for 50‑70 customer dashboards

When I joined, the team updated its customer dashboards by hand, which took about 7 days each time.

I created a central sheet of policies and customers, then wrote a Python script that works through it. For each policy, it opens the system, extracts the data, uploads it to the right sheet, and records that the dashboard is updated.

Input

Policy and customer records, plus data held in the company's system

Work

Python automation with gspread and PyAutoGUI, feeding Google Sheets and Looker Studio dashboards

Output

Insurance · Beyond Insurance Brokerage · 2023 to 2025

Loss ratio alerts and fraud analysis

I consolidated policy data in BigQuery and calculated each policy's loss ratio. A Python script then emails the customer when a policy passes a set limit.

I also ran fraud detection analysis, using statistical outlier detection and risk scoring based on ICD-10, the international standard for diagnosis codes.

Input

Contracts, claims, services and member utilization data

Work

BigQuery model, loss ratio calculation, Python email alerts, outlier detection and ICD-10 risk scoring

Output

Customers engaged with the numbersOne customer asked to meet about actions to reduce losses. The analysis also identified high-risk members and abnormal utilization

Healthcare · National Cancer Institute · 2023 to 2025

An IV label app, built from inside the pharmacy

Printing IV medication labels once took 4 dedicated pharmacists. While working part time at the institute, I studied Python seriously and built a desktop app that reads orders from Google Sheets, calculates mL doses from mg, and produces print-ready labels with Arabic text.

It targets the dose conversion and patient information errors that came with manual work. It was my first project in real use, and the institute still relies on it.

Input

Medication orders in Google Sheets, plus a drug reference sheet

Work

Python desktop app with Tkinter, gspread, Pandas and PDF label generation

Output

250-300 labels a day, handled by 1 pharmacistThat pharmacist also covers other duties, where the task once needed 4 people

Graduation project · Computer Science diploma · 2026

PharmAssist: from a label app to a full pharmacy workflow

PharmAssist grew out of the label app. It follows a medication order from physician to pharmacist to nurse. It warns about drug interactions before an order is submitted, records a timestamped history of each status change, and generates labels.

I wrote the code and Omar Reda Abdallah wrote the documentation, supervised by Dr. Sara Saad. It's an academic project and has not been deployed in a hospital.

Input

Demo patients, drugs, drug interactions and medication orders

Work

Django, SQLite and Bootstrap, with separate access for administrators, physicians, pharmacists and nurses

Output

Graded 99/100A working web app covering 16 documented use cases
